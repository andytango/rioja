# Content and style guidelines

## Typography and capitalization

### Sentence case for all headings and titles
**Always use sentence case (only capitalize the first word and proper nouns) for:**
- Blog post titles
- Page titles
- H2, H3, H4 headings within content
- Navigation labels
- Button text (where appropriate)

**Examples:**
- ✓ "Strategy by other means"
- ✗ "Strategy by Other Means"
- ✓ "The execution: AI as a collaborator"
- ✗ "The Execution: AI as a Collaborator"
- ✓ "Moving forward"
- ✗ "Moving Forward"

**Exceptions:**
- Proper nouns (e.g., "GitHub", "JavaScript", "Claude Code")
- Acronyms (e.g., "API", "CSS", "HTML")
- Brand names (e.g., "AstroJS", "LinkedIn")

### Rationale
Sentence case creates a more refined, editorial aesthetic that aligns with the site's focus on thoughtful, long-form content. It's more approachable than title case while maintaining professionalism.

## Content principles

### Clarity over cleverness
Write clearly and directly. Avoid jargon unless it serves the audience.

### Show, don't tell
Use examples and specifics rather than abstractions.

### Respect the reader's time
Get to the point quickly. Use headings to create clear structure.

## Technical standards

### Performance
- Optimize images (WebP format preferred)
- Preload critical assets
- Minimize JavaScript
- Use static site generation where possible

### Accessibility
- Semantic HTML
- Proper heading hierarchy
- Alt text for images
- Adequate color contrast

### Typography
- Berkeley Mono for headings and code
- Noto Sans for body text
- Generous paragraph spacing (24px)
- Ample heading margins (64px top, 24px bottom for H2)

## Agent instructions

When creating or editing content:
1. **Always convert titles and headings to sentence case**
2. Maintain consistent spacing and typography
3. Focus on performance and accessibility
4. Follow the established design system
5. Test changes in the preview environment before deployment
