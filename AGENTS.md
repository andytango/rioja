# Content and style guidelines

## Language and localisation

### British English
All content must use British English spelling and conventions:
- Use -ise endings (organise, realise, recognise)
- Use -our endings (colour, favour, behaviour)
- Use -re endings (centre, theatre)
- Use -ence endings (defence, licence as noun)
- Other British spellings (vapourware, rigourous, grey)

**Examples:**
- ✓ "democratised", "vapourware", "rigourous"
- ✗ "democratized", "vaporware", "rigorous"

## Typography and capitalisation

### Sentence case for all headings and titles
**Always use sentence case (only capitalise the first word and proper nouns) for:**
- Blog post titles
- Page titles
- H2, H3, H4 headings within content
- Navigation labels
- Button text (where appropriate)

**Examples:**
- ✓ "Strategy by other means"
- ✗ "Strategy by Other Means"
- ✓ "The execution: AI as a collaborator"
- ✗ "The Execution: AI as a Collaborator"
- ✓ "Moving forward"
- ✗ "Moving Forward"

**Exceptions:**
- Proper nouns (e.g., "GitHub", "JavaScript", "Claude Code")
- Acronyms (e.g., "API", "CSS", "HTML")
- Brand names (e.g., "AstroJS", "LinkedIn")

### Rationale
Sentence case creates a more refined, editorial aesthetic that aligns with the site's focus on thoughtful, long-form content. It's more approachable than title case whilst maintaining professionalism.

## Punctuation

### Em dashes
**Never use em dashes (—).** Instead, use punctuation that clarifies the relationship between clauses:

**Use colons (:)** for elaboration or expansion of an idea:
- ✓ "The challenge isn't just getting something to work: it's building something that scales."
- ✗ "The challenge isn't just getting something to work — it's building something that scales."

**Use semicolons (;)** for closely related independent clauses:
- ✓ "Structure and creativity are not opposing forces; they are partners."
- ✗ "Structure and creativity are not opposing forces — they are partners."

**Use parentheses ( )** for parenthetical information or asides:
- ✓ "I bring an empiricist's mindset (grounded in systems design and metrics) to ensure scalability."
- ✗ "I bring an empiricist's mindset — grounded in systems design and metrics — to ensure scalability."

**Use commas (,)** for lighter parenthetical phrases or lists:
- ✓ "The solution, built over several months, finally launched."
- ✗ "The solution — built over several months — finally launched."

### Rationale
British editorial style discourages em dashes in formal writing. Using more precise punctuation (colons, semicolons, parentheses) clarifies the relationship between ideas and improves readability. Each mark serves a distinct purpose rather than using em dashes as a catch-all.

## Content principles

### Clarity over cleverness
Write clearly and directly. Avoid jargon unless it serves the audience.

### Show, don't tell
Use examples and specifics rather than abstractions.

### Respect the reader's time
Get to the point quickly. Use headings to create clear structure.

## Technical standards

### Performance
- Optimise images (WebP format preferred)
- Preload critical assets
- Minimise JavaScript
- Use static site generation where possible

### Accessibility
- Semantic HTML
- Proper heading hierarchy
- Alt text for images
- Adequate colour contrast

### Typography
- Berkeley Mono for headings and code
- Noto Sans for body text
- Generous paragraph spacing (24px)
- Ample heading margins (64px top, 24px bottom for H2)

## Agent instructions

When creating or editing content:
1. **Always use British English spelling and vocabulary**
2. **Always convert titles and headings to sentence case**
3. **Never use em dashes** - use colons, semicolons, parentheses, or commas instead
4. Maintain consistent spacing and typography
5. Focus on performance and accessibility
6. Follow the established design system
7. Test changes in the preview environment before deployment
